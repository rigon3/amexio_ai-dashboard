# amexio_ai-dashboard

HR dashboard with AI elements for Amexio — a multi-page web dashboard backed by a
FastAPI service that provides training-budget analytics, an ML spend forecast, and
natural-language summaries generated by a local LLM (Ollama).

## Prerequisites

- Python 3.11+
- [Ollama](https://ollama.com) installed and running, with the model pulled:
  ```
  ollama pull llama3.1:8b
  ```
- The synthetic Excel data files placed in `backend/data/` (not committed):
  - `opleiding_export_synthetic.xlsx`
  - `medewerkers_overzicht_synthetic.xlsx`
  - `IKB_overview_export_synthetic.xlsx`
  - (plus the other synthetic exports)
- The trained forecast model at `model/model_random_forest.pkl`

## Setup & run (full features)

### 1. Backend

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate            # Windows  (use: source .venv/bin/activate on macOS/Linux)
pip install -r requirements.txt
```

### 2. Generate the monthly training-budget data  ← required for the time filters

The Monthly / Quarterly / Yearly filters need one export per month. Generate 12
months for 2026 from the base file (reproducible, fixed seed):

```bash
python generate_monthly_data.py
```

This creates `backend/data/opleiding_monthly/` (git-ignored).

### 3. Start Ollama

Make sure Ollama is running and `llama3.1:8b` is pulled (see Prerequisites).
The `/summary` endpoint calls it locally.

### 4. Start the backend

```bash
uvicorn main:app --reload      # serves http://127.0.0.1:8000
```

### 5. Open the frontend

The frontend is static HTML/CSS/JS in `frontend/`. Open any page in a browser, e.g.
`frontend/Home.html` or `frontend/training_budget.html`. The pages call the backend
at `http://127.0.0.1:8000` (CORS is open for local dev).

> Optional: serve the folder instead of opening files directly:
> ```bash
> cd frontend
> python -m http.server 5500
> ```
> then visit http://127.0.0.1:5500/Home.html

## Backend endpoints

| Endpoint | Method | Purpose |
|---|---|---|
| `/data?period=&month=` | GET | Training-budget aggregation (monthly/quarterly/yearly) |
| `/summary?view=&period=` | POST | LLM Brief + Standard summary for a view |
| `/forecast` | GET | ML next-month spend prediction |
| `/employees` | GET | Employee roster |

## Features by page

- **Training Budget** — period filters, KPIs, chart, table, ML forecast, AI summary (live)
- **Employees** — roster, charts, AI workforce summary (live)
- **Home / Sick Leave** — components are mounted but **stubbed**: the AI summary returns a
  "pending" message until each view's data source and prompt are implemented.

## Adding a real summary for a stubbed view

In `backend/llm.py`:
1. Write a context builder `_build_<view>(period, month)` returning `(system_prompt, user_message)`.
2. Add it to `VIEW_BUILDERS`.
3. Remove that view from `STUB_VIEWS`.

The frontend needs no change — the mounted component starts producing real output.
